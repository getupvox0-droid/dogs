# 3단계 설계: 함께하는 느낌

로드맵 3단계(무지개다리 공원, 함께 나눈 삶, 오늘의 강아지)를 어떻게 만들지 정리한 문서입니다. 착수 전에 아래 "정해야 할 것"을 먼저 결정합니다.

## 한눈에 보기

세 기능 중 둘은 **서버 없이** 만들 수 있습니다. 게임이 시드 기반이라, 시드와 선택 기록만 있으면 같은 삶을 누구의 브라우저에서든 그대로 다시 만들 수 있기 때문입니다.

| 순서 | 기능 | 서버 | 핵심 |
| --- | --- | --- | --- |
| 3-0 | 배포 | 정적 호스팅만 | 공유하려면 먼저 주소가 있어야 함 |
| 3-1 | 오늘의 강아지 | 필요 없음 | 날짜로 시드를 정해 모두가 같은 강아지로 시작 |
| 3-2 | 삶 공유 링크 | 필요 없음 | 시드 + 선택을 주소에 담아, 받은 사람이 그 삶을 다시 봄 |
| 3-3 | 무지개다리 공원 | 필요 | 다 산 강아지를 남기고 촛불을 켜는 추모 공간 |
| 3-4 | 함께 나눈 삶 | 필요 (3-3 재사용) | 다른 사람이 살아 본 삶과 한 줄 소감 |

서버가 필요한 3-3 이전까지는 비용과 운영 부담이 없습니다.

## 지키는 원칙

로드맵의 원칙을 함께하는 기능에도 그대로 적용합니다.

- **순위를 만들지 않는다.** 촛불 수로 정렬하거나 "인기 삶"을 보여주지 않습니다. 공원과 피드는 최신순이나 무작위로만 보여줍니다. 강아지는 비교하지 않습니다.
- **판단하는 말을 게임이 만들지 않는다.** 공유 화면에 들어가는 문장은 이미 게임에 있는 기록(도감 갈래, 가장 중요한 순간, 마지막 한 문장)만 씁니다.
- **개인 정보를 받지 않는다.** 로그인, 이메일, 실제 이름은 받지 않습니다. "우리 집 강아지" 프로필은 지금처럼 기기 밖으로 나가지 않습니다.
- **사람이 쓰는 글은 하나뿐.** 공원의 한마디, 피드의 한 줄 소감만 자유 입력이고, 길이를 짧게 제한합니다.

## 3-0. 배포

지금은 배포된 주소가 없습니다 (GitHub Pages도 꺼져 있음). `dist/`가 그대로 정적 사이트라 어디든 올릴 수 있습니다.

- **결정: Cloudflare Pages.** 3-3에서 쓸 Workers·D1과 같은 곳이라 나중에 옮길 필요가 없습니다.
- 대안: GitHub Pages. 설정이 가장 간단하지만, 3-3에서 서버는 따로 두어야 합니다.
- 배포 전에 할 일: `npm run build`(이미지 복원)를 배포 과정에 넣기, 공유 미리보기용 `og:image`·`og:title` 추가.

## 3-1. 오늘의 강아지 (서버 없음)

하루에 한 마리, 모든 사람이 같은 강아지로 태어납니다.

**만드는 법**
- 한국 시간 날짜(예: `2026-11-03`)로 시드를 정합니다: `seed = hash('daily:' + 날짜)`.
- `lifeId`도 `daily-2026-11-03`으로 고정합니다. 출생 장소 조합이 `lifeId`에 따라 달라지기 때문에, 이것까지 같아야 같은 강아지가 나옵니다.
- 출생일도 그날로 고정합니다 (`setBirthDate`).
- 첫 화면에 "오늘의 강아지로 태어나기" 버튼을 추가합니다.

**같은 점과 다른 점**
- 태어나는 곳, 외형, 성향, 형제는 모두 같습니다.
- 선택이 달라지면 이후 삶이 갈라집니다. "같은 강아지, 다른 삶"이 이 기능의 재미입니다.
- 엔딩에서 "오늘의 강아지는 이렇게 살았습니다"로 3-2 공유 링크를 바로 만들 수 있게 합니다.

**확인한 것**
- 같은 시드·`lifeId`·출생일에 같은 선택을 주면, 20개 생애 모두 기록이 한 글자도 다르지 않게 재현됐습니다.

**정해야 할 것**
- 오늘의 강아지는 "현실 비율"로 뽑을지, "골고루"로 뽑을지.

## 3-2. 삶 공유 링크 (서버 없음)

한 생을 주소 하나로 보냅니다. 받은 사람은 그 삶을 처음부터 읽기 전용으로 다시 봅니다. 기존 "처음부터 다시 보기" 화면을 그대로 씁니다.

**주소에 담는 것**
- 형식 버전, 시드, `lifeId`, 출생일, 출생 기준, 한 생의 길이
- 선택마다 "몇 번째 보기를 골랐는지" (보기는 2~4개라 선택 하나에 2비트면 충분)
- 예: 선택 80번이면 약 20바이트. 전체를 base64url로 바꿔도 100자 안팎입니다.
- 예: `https://…/#life=v1.8f3a….2026-11-03.real.short.AbC9…`
- 주소의 `#` 뒤에 두면 서버로 전송되지 않습니다.

**다시 만드는 법**
- 받은 쪽에서 엔진으로 같은 삶을 처음부터 다시 계산합니다. 한 생 계산은 약 60ms입니다 (개발 PC 기준).
- 엔진 버전이 바뀌면 같은 시드라도 다른 삶이 나옵니다. 그래서 주소에 형식 버전을 넣고, 오래된 링크는 "이전 버전에서 만든 삶이라 열 수 없습니다"라고 안내합니다. 엔진이 바뀔 때마다 이 버전을 올립니다.

**주의할 점**
- **관찰 모드의 자동 선택.** 관찰 모드는 자동으로 고를 때 난수를 씁니다. 그래서 자동으로 고른 선택은 따로 표시해 두고, 다시 볼 때도 같은 방식으로 난수를 소비해야 합니다. 착수할 때 테스트로 먼저 고정합니다.
- **고를 수 없게 된 선택.** 친구를 만날 수 없어서 선택이 무효가 된 경우(`dog-meet`)도 기록에 넣어야 합니다.
- **열어 보기 전에는 내용을 알 수 없음.** 주소만 보고는 어떤 삶인지 모르므로, 받은 사람은 바로 엔딩 카드부터 보게 합니다.

## 3-3. 무지개다리 공원 (서버 필요)

다 산 강아지를 공원에 남기고, 다른 사람이 촛불을 켜고 한마디를 남깁니다.

**남기는 것**
- 도감 기록 그대로: 이름, 품종, 나라, 출생 환경, 산 기간, 삶의 갈래, 가장 오래 곁에 있던 존재, 마지막 한 문장
- 3-2 공유 코드: 누르면 그 삶을 다시 볼 수 있습니다.
- 남기는 사람의 한마디 (선택, 최대 60자)

**보는 것**
- 공원은 최신순과 "아무나 한 마리" 두 가지로만 봅니다.
- 촛불 수는 그 강아지 카드에만 작게 보여주고, 정렬에는 쓰지 않습니다.
- 촛불에는 글을 붙이지 않습니다. 같은 기기에서 한 강아지에 한 번만 켤 수 있습니다.

**추천 구성: Cloudflare Workers + D1 + Turnstile**

| 선택지 | 좋은 점 | 아쉬운 점 |
| --- | --- | --- |
| **Cloudflare Workers + D1** (추천) | 정적 사이트와 같은 곳, SQL, 스팸 방지(Turnstile) 내장, 작은 규모는 무료 범위에서 시작 가능 | 무료 플랜은 요청당 CPU 시간이 짧아 서버에서 삶을 다시 계산하기 어려움 |
| Supabase | Postgres, 행 단위 권한, 로그인 기능 | 무료 프로젝트는 오래 안 쓰면 멈춤, 로그인 없이 쓰려면 권한 설계가 까다로움 |
| Firebase | 실시간 갱신이 쉬움 | 구글 종속, 규칙 언어 학습 필요 |
| 직접 서버 | 자유도 | 운영과 비용 부담 |

가격과 무료 한도는 착수할 때 다시 확인합니다.

**데이터 (D1)**
```
memorials  id, created_at, code, name, breed, country, birth_home, age_days,
           paths, companion, last_line, message, candles, status, device_hash
candles    memorial_id, device_hash, created_at   -- (memorial_id, device_hash) 유일
reports    target_id, reason, device_hash, created_at
```

**API**
```
GET  /api/memorials?order=recent|random&cursor=…
POST /api/memorials          { code, entry, message, turnstile }
POST /api/memorials/:id/candle { turnstile }
POST /api/memorials/:id/report { reason }
```

**스팸과 악용 막기**
- 글을 쓰는 요청에는 Turnstile(사람 확인)을 붙입니다. 사용자가 퍼즐을 풀 필요는 대부분 없습니다.
- 기기 하나에 하루 몇 마리까지만 남길 수 있게 합니다.
- 한마디에는 링크를 넣을 수 없고, 간단한 금칙어 목록을 거칩니다.
- 신고가 3번 쌓이면 자동으로 숨기고, 관리자가 다시 판단합니다.
- 관리자 화면은 따로 만들지 않고, 처음에는 숨겨진 글을 확인하는 작은 페이지 하나로 시작합니다.
- **가짜 기록.** 한 생을 다시 계산하는 데 약 60ms가 걸려서 무료 플랜 서버에서 바로 검증하기는 어렵습니다. 처음에는 검증하지 않습니다. 게임 기록은 꾸며도 얻는 것이 없고, 문제가 되는 것은 자유 입력 한마디뿐이기 때문입니다. 필요해지면 유료 플랜이나 주기적인 일괄 검증으로 확인합니다.

**개인 정보**
- 기기 구분은 브라우저에 저장한 무작위 값을 서버에서 소금(salt)과 함께 해시해서만 씁니다.
- IP는 저장하지 않습니다. 요청 수 제한은 Cloudflare 쪽 기능을 씁니다.
- 공원에 남긴 강아지는 남긴 기기에서 지울 수 있게 합니다.

## 3-4. 함께 나눈 삶 (서버 필요, 3-3 재사용)

다른 사람이 살아 본 삶을 한 줄 소감과 함께 모아 봅니다. 공원과 같은 서버, 같은 테이블 구조를 씁니다.

- 공원과의 차이: 공원은 다 산 강아지를 기리는 곳이고, 피드는 "이런 삶도 있었다"를 나누는 곳입니다. 같은 삶을 양쪽에 올릴 수 있습니다.
- 피드에서는 "같은 시작에서 다른 선택"이 잘 보이도록, 오늘의 강아지(3-1)로 산 삶을 같은 날끼리 묶어 보여줍니다.
- 소감은 최대 40자입니다. 댓글과 답글은 만들지 않습니다.

## 순서와 규모

| 단계 | 대략의 작업 | 끝났다고 보는 기준 |
| --- | --- | --- |
| 3-0 배포 | 반나절 | 공개 주소에서 게임이 열리고, 공유 미리보기 이미지가 보임 |
| 3-1 오늘의 강아지 | 1일 | 두 브라우저에서 같은 날 같은 강아지로 태어남 (테스트로 고정) |
| 3-2 공유 링크 | 2~3일 | 직접 고른 삶과 관찰 모드의 삶 모두 링크로 똑같이 다시 열림 |
| 3-3 공원 | 4~5일 | 남기기, 촛불, 신고, 숨기기가 동작하고 스팸 방지가 켜져 있음 |
| 3-4 피드 | 2일 | 오늘의 강아지끼리 묶어 보기 |

## 정해야 할 것

1. ~~배포 위치~~ → **Cloudflare Pages로 결정**
2. **오늘의 강아지의 출생 기준**: 현실 비율로 할지, 골고루로 할지.
3. **실제 반려견 추모**: 공원을 게임 속 강아지 전용으로 둘지, 실제로 떠난 반려견도 남길 수 있게 할지. 실제 반려견을 받으면 사진, 사적인 글, 신고 대응 기준이 크게 달라지므로 처음에는 게임 속 강아지만 받는 것을 추천합니다.
4. **운영**: 신고된 글을 누가 얼마나 자주 확인할지. 3-3을 열기 전에 정해야 합니다.
